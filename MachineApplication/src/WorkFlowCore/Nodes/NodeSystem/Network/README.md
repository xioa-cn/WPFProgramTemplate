# TCP 连接与发送

TCP 连接节点与发送节点分离。Key 的作用域是同一工作流画布，去除首尾空白后不区分大小写；客户端与服务端共用这个名称空间，不允许两个运行中的连接节点占用同一个 Key。

## 服务端

1. 添加“TCP 服务端”，设置连接 Key 为 `tcp1`，设置监听地址、端口和接收长度。
2. 勾选“自动启动”，或通过属性面板的“启动 / 停止 TCP 连接”按钮启动。
3. 添加“TCP 服务端发送”，连接 Key 同样填写 `tcp1`。
4. 设置发送文本，或向“发送数据”端口传入 `byte[]` / 文本，再执行发送节点。

服务端连接节点只负责监听、接受客户端连接和后台接收，不发送固定回复，也没有发送输入端口。

服务端发送节点的“客户端 ID”为空时向当前连接的所有客户端广播。需要回复特定客户端时，将服务端的“客户端 ID”输出连接到发送节点同名输入端口；这个 ID 在该客户端连接存续期间有效，断开重连后会变化。服务端每次接收先更新客户端 ID，再输出收到数据和接收触发信号。

## 客户端

1. 添加“TCP 客户端”，设置连接 Key（例如 `tcpClient1`）、主机和端口。
2. 勾选“自动启动”和需要的“自动重连”。客户端会保持连接并独立接收数据。
3. 添加“TCP 客户端发送”，填写相同 Key；发送节点复用已有连接，不会每次重新建连，也不等待响应。
4. 响应从客户端连接节点的“收到数据”端口输出。

## 启停、重连与错误

- 自动启动默认关闭；仅在节点随页面实际显示后执行，读取文件和临时画布校验不会打开网络连接。
- 自动重连默认开启，间隔默认 1000 毫秒，可配置 100～600000 毫秒。客户端初次连接失败或检测到断线后按间隔重试；服务端监听失败时重新尝试监听，客户端断开不会停止服务端监听。
- 启动操作不阻塞等待网络连接建立；启动成功表示连接服务已启动，是否已连接或正在重试以节点状态为准。
- 页面卸载、节点删除或替换、手动停止以及启动上下文取消时关闭连接并释放 Key。页面返回后，启用自动启动的节点会重新启动；手动停止或上下文取消后的同一节点需要手动重新启动。
- 修改运行中的 Key、地址、端口或重连参数，需要先停止再启动；发送仍使用启动时注册的 Key。
- Key 不存在、类型不匹配、尚未连接、没有可发送的客户端或目标客户端已断开时，发送节点返回失败，不缓存消息，也不自动重放消息。
- 同一连接上的发送串行执行。发送超时可能已发送部分数据，连接会关闭，避免继续使用不完整的数据流；广播失败时也可能已有部分客户端收到数据，不应无条件重发。

## 接收长度

`接收长度 > 0` 时，按固定字节数组帧；从首字节到整帧接收完成受连接节点的超时控制。空闲连接不会仅因没有业务数据而被关闭。

`接收长度 = 0` 时，按每次网络读取的数据块输出，不再等待对端关闭。读取块不代表业务消息边界，需要按协议自行处理拆包、粘包。发送文本使用 UTF-8，不自动追加换行。

## 旧流程调整

旧版 TCP 客户端的发送文本和“接收响应”逻辑、服务端的固定回复逻辑不再执行。请将发送内容移到对应的新发送节点，并配置 Key。旧连接节点的发送输入端口已移除；保存文件中若仍有连接到该端口的连线，加载会拒绝该无效连接并保留当前画布，需要迁移连线，不能直接沿用旧端口。新增发送节点已登记到“网络通信”节点库，配置随工作流文件保存。

独立的“TCP 监听接收”单次连接节点维持原有行为，不作为 Key 连接服务使用。
